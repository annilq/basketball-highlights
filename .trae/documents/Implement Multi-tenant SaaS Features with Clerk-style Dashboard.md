# 实现多租户SaaS功能与Clerk风格仪表盘

## 1. 功能分析

根据项目需求和现有代码结构，我需要实现以下功能：

- 多租户SaaS功能（Organization管理）
- 成员管理（Member management）
- 基于角色的访问控制（Role-based access control）
- 邀请系统（Invitation system）

## 2. 技术栈与现有资源

### 现有资源

- **数据库**：已设计organization、member和invitation表
- **API路由**：已有organization.ts路由框架，需要实现具体逻辑
- **UI组件**：已有基础layout、sidebar和header组件

### 技术栈

- React + TypeScript
- TanStack Router
- Tailwind CSS
- tRPC
- Drizzle ORM

## 3. 实现计划

### 3.1 API实现

1. **完成organization.ts路由**：
   - 实现组织列表、创建、更新、删除功能
   - 实现成员列表、邀请、移除功能
   - 实现邀请状态管理

2. **完善user.ts路由**：
   - 添加用户角色管理功能

### 3.2 UI实现

1. **组织管理页面**：
   - 组织列表与创建
   - 组织详情与设置

2. **成员管理页面**：
   - 成员列表
   - 邀请成员表单
   - 角色分配与管理
   - 移除成员功能

3. **邀请管理页面**：
   - 待处理邀请列表
   - 已接受/拒绝邀请历史
   - 取消邀请功能

4. **角色管理**：
   - 角色权限展示
   - 角色分配功能

5. **导航更新**：
   - 添加组织、成员、邀请管理导航项

### 3.3 核心组件设计

1. **组织选择器**：允许用户在多组织间切换
2. **邀请表单**：支持批量邀请和角色指定
3. **成员卡片**：展示成员信息和角色
4. **角色选择器**：用于分配和编辑角色
5. **邀请状态指示器**：展示邀请的不同状态

## 4. 实现顺序

1. 先实现API路由的具体逻辑
2. 然后实现基础UI组件
3. 接着实现各个功能页面
4. 最后集成和测试

## 5. 设计参考（Clerk Dashboard风格）

- 简洁现代的设计风格
- 清晰的层级结构
- 直观的操作流程
- 良好的响应式设计
- 明确的权限反馈

## 6. 预期效果

- 用户可以创建和管理多个组织
- 组织所有者可以邀请成员并分配角色
- 成员可以接受或拒绝邀请
- 基于角色的权限控制
- 直观的仪表盘界面
